# 故障排查

常见问题见 [常见问题](faq.md)；已知限制见 [已知限制](limitations.md)。

平台身份模型的详细说明不在本知识库，位于 platform 领域的注册面知识库中，
这里只给出排查步骤。

## 同步失败

### 症状：同步成功但版本没有变化

不是故障。commit 变了但 package hash 没变，说明改动落在未被 manifest 选中的
文件上，或者内容确实相同。

排查顺序：确认改动的文件是否在 include 范围内 → 确认是否被 exclude 命中。

### 症状：来源状态变为 error

按以下顺序检查：

1. 仓库是否公开。当前远程同步只支持公开仓库。
2. 指定的 ref 是否存在。
3. package 路径是否存在于该 commit 下。
4. 根目录是否有 manifest 文件。KB package 缺少 `KNOWLEDGE.yaml` 会直接失败。

### 症状：报告包内出现多个根目录

归档的首个条目可能是元数据条目而非真实目录。如果自建的测试归档能通过但真实
仓库失败，几乎一定是这个原因。

## 检索问题

### 症状：搜不到刚加的内容

同步之后必须执行索引。检查该来源的索引状态：是否有 chunk 处于失败或待处理状态。

### 症状：中文查询结果很差

先看融合分。如果一批不同查询的分数全部等于 0.5，说明只有一条通路在工作，
不是巧合——这是单通路命中的分数上限。

### 症状：结果里出现了应该被排除的内容

确认 exclude 规则是否真的生效：被排除的文件不应出现在文档清单里。
如果它出现了，说明规则写法没有匹配到实际路径。

### 症状：换了 embedding 模型后结果混乱

向量集合的维度在创建时固定。换模型必须重建集合并全量重新索引，
只改环境变量会导致新旧向量混在一起，而且不会报错。

## 索引问题

### 症状：索引中止并报错误数超限

单个来源的失败 chunk 数超过阈值会中止，避免在供应商故障时空转。
先确认 embedding 供应商是否可用，再重新触发索引。

### 症状：删掉的文档还能被搜到

重新索引会清理旧 revision 的投影与当前 revision 中不再产生的 chunk。
如果仍然搜到，确认索引是否成功完成而不是中途中止。
